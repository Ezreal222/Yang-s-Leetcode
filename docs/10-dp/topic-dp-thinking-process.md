# 技巧 · DP 通用思维流程 (Thinking Process)

**EN**: A general-purpose workflow for attacking any DP problem: identify → three elements (state / transition / init) → loop order → boundary & optimization. The core method is "last-step thinking" for deriving transitions.

**中文**: 看到任何 DP 题该怎么想的一套通用流程: **识别题型 → DP 三要素 (状态/转移/初始) → 遍历顺序 → 边界与优化**. 推转移方程的万能钥匙是**"最后一步" 思维**.

---

## 第一步: 识别"这是不是 DP 题" / Is it DP?

| 信号 | 说明 | 例子 |
|---|---|---|
| **求最优** (max / min) | 最大/最小类问题 | [0322 零钱兑换](./0322-coin-change/README.md), [0343 整数拆分](./0343-integer-break/README.md) |
| **求方案数** (counting) | 多少种方法 | [0070 爬楼梯](./0070-climbing-stairs/README.md), [0518 零钱兑换 II](./0518-coin-change-ii/README.md) |
| **求能否** (judging) | 能不能达到 | [0416 分割等和子集](./0416-partition-equal-subset-sum/README.md) |
| **每步多个选择** | 选/不选, 选哪个 | 背包 (选/不选), [0343](./0343-integer-break/README.md) (第一刀切哪) |
| **子问题重叠** | 暴力递归会重复计算 | [0070](./0070-climbing-stairs/README.md) (斐波那契重复) |

**反面信号** (可能是贪心):

> 如果"每步选当前最优" 就能得到全局最优 → 通常是**贪心** (如 [0055 跳跃游戏](../09-greedy/0055-jump-game/README.md)). **DP 用在贪心失效, 需要保留所有子问题状态时**.

---

## 第二步: DP 三要素 (核心) / The Three Elements

### 要素 1: 状态定义 — `dp[i]` 表示什么? / State

**最关键、最难的一步**. 问自己:

> **"我需要记录什么信息, 才能推进到下一步?"**

常见状态模式:

| 状态形式 | 含义 | 例子 |
|---|---|---|
| `dp[i]` | 到第 i 个/前 i 个的某个量 | [0070 爬楼梯](./0070-climbing-stairs/README.md) (到第 i 阶方法数) |
| `dp[i][j]` | 二维 (网格/两序列/容量+物品) | [0063 网格](./0063-unique-paths-ii/README.md), [0474 二维背包](./0474-ones-and-zeroes/README.md) |
| `dp[i]` = **以 i 结尾** | 必须包含第 i 个 | 0300 LIS (待补) |

> **从"问什么" 反推状态**: 求"最少硬币数" → `dp[j] = 凑出 j 的最少硬币数`. 求"最长子序列" → `dp[i] = 以 i 结尾的最长长度`. **dp 通常就是"问题本身的子问题答案"**.

### 要素 2: 转移方程 — `dp[i]` 怎么从更小的推出来? / Transition

**🔑 用"最后一步" 思维 — 推转移方程的万能钥匙 / Last-step thinking**:

> **"到达 `dp[i]` 这个状态, 最后一步是什么? 最后一步有哪些可能?"**

把每种"最后一步" 对应的更小子问题组合起来:

| 题 | 最后一步是什么 | 转移 |
|---|---|---|
| [0070 爬楼梯](./0070-climbing-stairs/README.md) | 从 `i-1` 爬 1 或 `i-2` 爬 2 | `dp[i] = dp[i-1] + dp[i-2]` |
| [0063 网格](./0063-unique-paths-ii/README.md) | 从上来 或 从左来 | `dp[i][j] = dp[i-1][j] + dp[i][j-1]` |
| [0343 整数拆分](./0343-integer-break/README.md) | 第一刀切 j | `dp[i] = max_j(j × (i-j), j × dp[i-j])` |
| [0322 零钱兑换](./0322-coin-change/README.md) | 最后用一个 coin | `dp[j] = min(dp[j], dp[j-coin] + 1)` |
| 0/1 背包 | 当前物品**选/不选** | `dp[j] = max(dp[j], dp[j-w] + v)` |
| [0096 BST](./0096-unique-binary-search-trees/README.md) | 选 i 当根 | `dp[n] = Σ dp[i-1] × dp[n-i]` |

**转移运算反映"求什么"**:

| 求什么 | 转移运算 |
|---|---|
| 计数 | `+=` (累加方法数) |
| 最值 | `max` / `min` |
| 判定 | `\|\|` (或) |

### 要素 3: 初始条件 — 递推的地基 / Base case

> **dp 的"起点" 是什么? 最小的子问题答案是什么?**

**初始化看"求什么"**:

| 求什么 | 初始化 |
|---|---|
| 计数 | `dp[0] = 1` (空集算一种) |
| 最小 | `dp[0] = 0`, 其余 `INT_MAX` |
| 最大 | 全 0 或按题意 |
| 判定 | `dp[0] = true` |

> `dp[0]` 是最关键的种子 — 几乎所有递推从它开始. 计数题漏写 `dp[0] = 1` 整张表都是 0; 最值题漏写哨兵会取错初值.

## 第三步: 遍历顺序 / Loop Order

**核心原则: 算 `dp[i]` 时, 它依赖的子问题已经算好**:

| 类型 | 顺序 |
|---|---|
| 线性 DP | 一般从小到大 (i = 0 → n) |
| 网格 DP | 从左上到右下 |
| **0/1 背包** (一维) | 容量**倒序** |
| **完全背包** (一维) | 容量**正序** |
| 区间 DP | 按区间长度从小到大 |

> 0/1 vs 完全的倒序/正序对照见 [0416](./0416-partition-equal-subset-sum/README.md) vs [0518](./0518-coin-change-ii/README.md). 组合数 vs 排列数的循环顺序对照见 [0518](./0518-coin-change-ii/README.md) vs [0377](./0377-combination-sum-iv/README.md).

---

## 第四步: 边界 + 空间优化 / Boundary & Space

1. **边界**: 数组越界? `dp[0]` 特殊处理? 无解返回什么 (`-1`)?
2. **空间优化**: `dp[i]` 只依赖前几项 → 滚动变量/滚动数组. 见 [0070](./0070-climbing-stairs/README.md), [0509](./0509-fibonacci-number/README.md) 的 O(1) 版本.

## 完整流程图 / Workflow

```
看到题
  ↓
1. 是 DP 吗? (最优/计数/判定 + 多选择 + 子问题重叠)
  ↓ 是
2. DP 三要素 (核心):
   ├─ 状态:  dp[i] 表示什么?  ←  从"问什么" 反推
   ├─ 转移:  用"最后一步" 思维  ←  最后一步有哪些可能?
   └─ 初始:  dp[0] 是什么?    ←  看"求什么"
  ↓
3. 遍历顺序: 保证依赖的子问题先算好
  ↓
4. 边界 + 空间优化
  ↓
写代码
```

## 走流程示范: [0198 House Robber](./0198-house-robber/README.md) / 打家劫舍

**题目**: 一排房子, 每个有钱 `nums[i]`, 不能偷相邻的, 求最多偷多少.

```
1. 是 DP 吗?
   求"最多" (最优) + 每个房子"偷/不偷" (多选择) → 是 DP

2. 三要素:
   状态:  dp[i] = 偷到第 i 个房子时的最大金额
   转移:  最后一步 — 第 i 个房子"偷" 还是"不偷"?
          ├─ 偷:    dp[i-2] + nums[i]  (不能偷 i-1)
          └─ 不偷:  dp[i-1]
          dp[i] = max(dp[i-1], dp[i-2] + nums[i])
   初始:  dp[0] = nums[0], dp[1] = max(nums[0], nums[1])

3. 遍历: i 从 2 到 n-1

4. 优化: 只依赖前两项 → 滚动变量 O(1)
```

5 分钟从读题到框架 — 这就是流程的威力.

## DP 题型速查 / Common DP Types

| 类型 | 特征 | 代表题 |
|---|---|---|
| **线性 DP** | `dp[i]` 依赖前几项 | 0070 / 0198 / 0300 |
| **网格 DP** | 二维矩阵路径 | [0063](./0063-unique-paths-ii/README.md) / 0064 |
| **背包 DP** | 容量 + 物品选择 | [0416](./0416-partition-equal-subset-sum/README.md) / [0322](./0322-coin-change/README.md) (全套 [0416](./0416-partition-equal-subset-sum/README.md)–[0279](./0279-perfect-squares/README.md)) |
| **序列 DP** | 子序列/子数组 | 0300 (LIS) / 0053 |
| **双序列 DP** | 两个字符串/数组 | 1143 (LCS) / 0072 |
| **区间 DP** | 区间合并 | 0312 / 0516 |
| **状态机 DP** | 多状态转移 | 股票买卖 0121 系列 |

> 看到题先归类 → 套对应的状态模式 → 推转移. 跟"折半搜索" 那个 topic 一样, 归类是减少思考量的捷径.

## 推转移卡住时的技巧 / When stuck on transition

如果"最后一步" 一时想不出来:

1. **画小例子**: n = 1, 2, 3 手算, 找规律.
2. **从暴力递归出发**: 先写朴素穷举递归, 再加记忆化 → 自然得到 DP. (DP = 记忆化的穷举.)
3. **问"以 i 结尾"**: 序列题常用 "`dp[i]` = 以 i 结尾的某量".
4. **问"选/不选"**: 每个元素的二元选择 (背包思想).
5. **问"枚举分割点"**: 区间/拆分题枚举中间点 — 见 [0343](./0343-integer-break/README.md), [0096](./0096-unique-binary-search-trees/README.md).

## 一句话总结 / TL;DR

> 看到 DP: ① 识别是 DP (最优/计数/判定 + 多选择 + 子问题重叠) → ② **三要素**: 状态 (从"问什么" 反推)、转移 (**"最后一步" 思维**)、初始 (看"求什么" 定 `dp[0]`) → ③ 遍历顺序 (依赖先算) → ④ 边界 + 空间优化.

### 记忆要点

1. **识别**: 最优/计数/判定 + 每步多选择 + 子问题重叠.
2. **状态**: `dp[i]` 表示什么 — 从"问什么" 反推.
3. **转移**: **"最后一步" 思维** — 最后一步有哪些可能? 用 `+` / `max` / `min` / `||` 组合更小子问题.
4. **初始**: `dp[0]` — 计数 1 / 最小 INT_MAX / 最大 0 / 判定 true.
5. **遍历**: 保证依赖的子问题先算好.

### 跟"贪心思维流程" 的关系

| | 贪心 | DP |
|---|---|---|
| 思路 | 每步选当前最优 | 保留所有子问题状态 |
| 适用 | 局部最优 = 全局最优时 | 贪心失效时 |
| 速度 | 更快 (常 O(n)) | 通用但更慢 |

**能贪心就贪心, 不能才 DP**. 详见 [§09 贪心算法](../09-greedy/index.md).
